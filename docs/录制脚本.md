# Smart AI 功能演示录制脚本（5:50，男声旁白版）

> **内部使用，不是评委材料。** 本文件是给参赛者边看边操作的录制手册；视频完成后请删除本文件，并从 README 移除链接。
>
> 成片：**5 分 38 秒**，1920×1080，男声旁白 + 同步字幕。  
> 旁白：`zh-CN-YunxiNeural`，年轻男声，语速 `-4%`，音高 `+3Hz`；字幕与旁白逐字一致，不做二次改写。  
> 不写“各位老师好 / 今天演示 / 谢谢大家”之类的开场和客套，第一句直接讲产品。

---

## 一、录制前准备

### 1. 启动

双击项目根目录的 `start.bat`，等浏览器打开 `http://localhost:3000`。  
如果要展示 DeepSeek，先确认 `.env` 已配置 `DEEPSEEK_API_KEY`；任务页出现“DeepSeek 解析”标签才算生效。

### 2. 浏览器

- Edge 或 Chrome，窗口最大化，缩放 **100%**。
- `Ctrl + Shift + B` 隐藏书签栏。
- 关闭微信、QQ、系统通知；手机静音。
- 准备 4 个标签页：

| 标签 | 地址 | 用途 |
|---|---|---|
| Tab 1 | `http://localhost:3000/` | 主流程 |
| Tab 2 | 预先建好的“2024 无证据”任务 | fail-closed 演示 |
| Tab 3 | `http://localhost:3000/documents` | 文档解析 |
| Tab 4 | `http://localhost:3000/onboarding` | 无障碍 |

**Tab 2 先建好：**

1. 打开 `http://localhost:3000/task/new`。
2. 描述输入：`居民医保缴费`。
3. 点“识别事项”。
4. 地区填：`西藏自治区`；年份填：`2024`。
5. 点“继续梳理”。
6. 看到“没有找到适用的政策证据”后，**不要关闭、不要刷新**。

### 3. 材料

- `演示材料.png`：任务工作台“材料格式检查”用；仓库自带 `docs/assets/演示材料.png`，复制到桌面。
- `演示材料.pdf`：文档解析页用；任意 PDF，文件名改成 `演示材料.pdf`。

### 4. 配音与字幕

- 旁白按下面的 15 段生成；每段单独一个音频，段间留 0.8 秒。
- 字幕就是每段旁白原文，出现时间与音频起点对齐；不要另写短句，否则会出现“声画不同步”。
- 人声做轻度压缩和响度统一即可，不要加背景音乐，避免盖住讲解。

## 三、旁白全文（字幕同文）

### 1（0:00）

Smart AI 明白办，面向老年人、残障人士和低数字素养人群。它把复杂的公共服务办理，拆成一条看得懂、办得对、可以随时确认的任务；先理解用户的一句话，再把办理步骤拆开，最后给出有依据的下一步。

### 2（0:19）

覆盖城乡居民医保、高校学生资助、老年与残障服务三类场景。匿名进入，不需要账号；示例人物是虚构的，政策库为公开政策摘要。首页可以直接进入三类事项，也可以先调整阅读方式。

### 3（0:40）

先看 DeepSeek 接入。用户只需要描述一句话，系统就会识别事项类型，抽取用户已经提供的事实，并生成一句话摘要。发送之前，手机号和身份证号会先脱敏；模型只负责理解，不负责下政策结论，超时或失败会自动回退规则。结构化输出会经过 JSON 校验，避免模型跑偏。

### 4（1:08）

所以缺少地区、年份这些关键信息时，系统先追问，不直接给判断。把补充信息的动作留在用户手里，避免拿错地区、用错年份，也避免用一句模糊的话生成看似完整的答案。追问不是打断，而是把判断条件补齐。

### 5（1:30）

补充演示地区和 2026 年，继续梳理。左侧任务时间线从理解需求、补充信息，推进到检索政策、检查材料和人工确认，用户始终知道现在走到哪一步。刷新页面后，任务、地区和年份仍然可以恢复。

### 6（1:51）

检索结果不是一段笼统的回答，而是一张证据卡。事项、地区、有效期、条款、来源、适用理由，缺一不可。证据卡展示政策库摘要和官方来源，不把摘要冒充正式条文；没有来源，就不下结论。来源链接和适用理由一并展示，方便用户核对。

### 7（2:17）

材料检查只读取浏览器提供的文件类型和大小，不读取文件内容，不执行 OCR，也不生成虚构的质量评分。原始文件不会上传，演示页面会明确写出这条边界。任务工作台接受 JPG、PNG、PDF，大小不超过 10MB。

### 8（2:40）

知情确认只是记录用户已经了解演示范围。按钮变成已记录确认，任务停在待人工确认，但这不等于正式提交，也不代表资格认定；系统只记录最小审计字段。审计只记录任务 ID、事件类型、风险级别和时间。

### 9（3:01）

办理指南把下一步拆成三条可执行动作；家属协助清单把帮忙变成可核对的步骤。勾选状态只保存在当前浏览器，不会同步给任何部门，也不会自动提交申请。家属清单是四步核对，刷新后仍然保留。

### 10（3:22）

如果换成一个没有覆盖的年份，比如 2024 年，系统直接说明没有找到适用证据，不会编一个看似合理的答案。宁可少答，不可错答，这是政策场景必须守住的底线。系统不会用模型补答案，也不会把不确定说成确定。

### 11（3:42）

文档解析支持 PDF、DOCX、TXT 和 PNG、JPG 图片。上传后提取文本、页数和字数，图片在本地做 OCR 并返回置信度，文件只在本次请求中读取，服务端不保存。扫描版 PDF 可以先转成图片再识别。PDF 支持多页文本，DOCX 提取正文，TXT 直接解码。

### 12（4:11）

无障碍支持 100% 到 175% 字体、高对比度、键盘焦点和语音播报；浏览器不支持语音时，自动保留文字路径，不会把用户卡在语音功能上。设置保存在本机浏览器，随时可以调回。还有跳过导航、清晰焦点和文字替代。

### 13（4:33）

工程侧有 22 项单元测试、20 项端到端用例，覆盖追问、无证据、会话隔离、文档解析和图片 OCR；RAG 十组评测全部通过。CI 包含 lint、构建、浏览器测试和容器健康检查，每次提交自动执行。政策库管理页可以新增、删除条目，Docker standalone 构建和健康检查也已准备。

### 14（4:54）

当前还没有接真实地方政策库的逐条复核和扫描版 PDF 逐页 OCR；任务、政策、审计写入 SQLite，重启可以恢复，但单进程 SQLite 不支持多副本和 Serverless。这些限制写进了验收清单，演示时不会把能力说满。公网部署、HTTPS 和多实例还没有验收。

### 15（5:15）

我们想做的，不是替用户做决定，而是把办理路径讲清楚，把政策依据摆出来，把能力边界说明白。让每一次办理，都不再靠猜。这是产品的底线，也是这次演示想说明的事。
