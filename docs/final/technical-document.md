# Smart AI（明白办）技术文档

## 1. 项目概述

Smart AI（明白办）面向老年人、残障人士、家属和低数字素养人群，把公共服务办理需求转化为清楚、可确认、可追溯的任务：识别事项、追问地区与年份、检索政策证据、检查材料、提示风险并交由用户确认。

完整参赛版覆盖三类事项：

1. 城乡居民医保参保缴费；
2. 高校学生资助申请；
3. 老年人与残障人士公共服务材料办理。

## 2. 用户痛点与场景

- 政策表述复杂，不清楚办理顺序；
- 地区、年份、身份条件不同，容易用错政策；
- 不确定材料是否齐全；
- 老年人、残障人士需要大字体、语音和家属协助；
- 担心上传证件造成隐私泄露。

## 3. 功能架构

首页、无障碍设置、任务工作台、材料检查、文档解析、办理指南、家属协助、政策库管理和健康检查组成主要界面；Route Handlers 提供任务、对话、政策检索、材料元数据、文档解析、政策管理和风险确认接口。

## 4. 系统总体架构

前端使用 Next.js App Router、React、TypeScript；服务端使用 Next.js Route Handlers。任务、会话归属、审计事件和 30 条政策库写入 Node 内置 SQLite（`node:sqlite`），默认文件 `.data/smart-ai.sqlite`，服务重启后保留。

DeepSeek 为可选事项识别/摘要层；图片 OCR 使用 Tesseract.js 在服务端本地运行。Prisma/PostgreSQL schema 仅作为后续大规模语料的迁移参考，当前运行路径不依赖 PostgreSQL。

## 5. 任务与 Agent 工作流

任务按“理解需求 → 补充信息 → 检索政策 → 检查材料 → 人工确认 → 生成指南”推进。

- 未识别事项先追问；
- 医保事项需要地区和年份；
- 事项分类可选调用 DeepSeek 做结构化识别，未配置或调用失败时回退规则；
- 风险分级由规则完成；
- 没有适用证据时 fail-closed，不生成确定性结论。

## 6. 政策库与证据

内置 30 条政策摘要，三场景各 10 条，覆盖全国及北京、上海、广东等地区。每条包含：

- 政策名称、事项、地区；
- 生效/失效日期；
- 条款或摘要；
- 官方来源 URL；
- 章节、初始相关度、适用理由。

检索采用“事项 + 地区 + 时间”硬过滤，再加关键词命中排序：

- 地方库有匹配时，地方条目优先，同时保留全国条目兜底；
- 地方没有匹配时返回全国政策摘要，并明确提示地方标准需核对；
- 学生资助、老年/残障服务与医保使用同一套检索路径，不做医疗硬编码。

政策库可在 `/admin/policies` 新增、删除；配置 `ADMIN_TOKEN` 后写操作需要口令。正式上线前需由业务人员逐条复核政策原文。

## 7. 多模态与材料

浏览器支持时使用原生 Web Speech API 做语音输入/播报降级。

任务工作台的材料检查只接收 MIME 类型和文件大小，不接收文件字节、不执行 OCR、不生成虚构质量分。

独立的 `/documents` 页面支持：

- PDF：`pdf-parse` 提取多页文本；
- DOCX：`mammoth` 提取正文；
- TXT：UTF-8/GBK 解码；
- PNG/JPG/WEBP：Tesseract.js 中文+英文 OCR，返回置信度。

文件只在请求内读取，不保存。扫描版 PDF 当前建议转为图片后 OCR。

## 8. 隐私、安全与审计

任务创建及追问在写入 SQLite 前对手机号/身份证号脱敏；发送给 DeepSeek 的文本同样先脱敏。

- 任务 ID 使用 UUID，任务页与变更接口检查匿名会话归属；
- 会话和任务默认 24 小时过期；
- 审计只记录任务 ID、事件类型、风险级别与时间；
- 政策库写操作可用 `ADMIN_TOKEN` 保护；
- 真实证件、银行卡、病历不应上传；
- `.env`、`.data`、上传目录不进入 Git。

知情确认不等于正式办理，也不代表资格认定。

## 9. 无障碍设计

支持 100%、125%、150%、175% 字体、高对比度、键盘焦点、跳过导航、文字替代、语音输入/播报降级和家属协助清单。设置和清单保存在本机浏览器。

## 10. API 与异常处理

API 使用 Zod 校验；客户端提供超时、网络错误提示及保留输入的重试。

主要接口：

- `POST /api/tasks`：创建任务，可选 DeepSeek 解析；
- `POST /api/chat`：补充地区/年份，检索政策证据；
- `POST /api/documents`：材料元数据检查；
- `POST /api/documents/parse`：PDF/DOCX/TXT/图片解析与 OCR；
- `GET/POST/DELETE /api/policies`：政策库管理；
- `POST /api/confirmations`：知情确认与审计；
- `GET /api/health`：服务、SQLite、模型与 OCR 状态。

解析失败返回 400/413/415/422 等可控错误；健康接口返回 `storage: "sqlite"`、`ocrEnabled: true` 和 `policyCount`。

## 11. 数据模型

SQLite 运行表：

- `tasks`：任务、消息、地区/年份、证据 JSON、计划、状态、风险、分析来源；
- `policies`：政策摘要、地区、有效期、来源、相关度；
- `audit_events`：最小审计字段。

`prisma/schema.prisma` 保留 User/Task/Message/Document/PolicyChunk/Evidence 关系模型，作为迁移 PostgreSQL/pgvector 的参考。

## 12. 测试与评测

- 22 项 Vitest 单元测试：脱敏、确认、会话、检索边界、超时、文档解析；
- 20 项 Playwright 端到端测试：桌面与 390px 移动布局；
- RAG 10 组评测：事项、地区、时间、跨事项不混检、无证据拒答；
- `npm run lint`、`npm run typecheck`、`npm run build` 均通过；
- Docker 构建与健康检查由 CI 执行。

## 13. 部署

提供 Next.js standalone、Docker 单实例、Docker Compose、Caddy 自动 HTTPS、健康检查和 CI。

- 运行时使用单进程 SQLite，Docker Compose 把 `/app/data` 挂载为持久卷；
- 不支持多副本共享写入或 Serverless；
- DeepSeek 密钥、管理口令通过服务端环境变量注入，不写入镜像或仓库；
- 公网部署与 HTTPS 需要在目标服务器执行并验收。

## 14. 创新点

1. 把公共服务咨询拆成用户可见的任务状态，而不是普通聊天框；
2. 政策结论绑定证据，证据不足明确兜底；
3. 三场景共用一套政策库、检索和证据协议，不是单点 Demo；
4. 任务、政策、审计持久化到 SQLite，重启可恢复；
5. 图片 OCR、文档解析、语音输入和家属协助覆盖多模态与无障碍；
6. 对敏感信息、材料读取和正式提交设定清楚边界。

## 15. 社会价值与展望

系统降低公共服务的数字门槛，让老年人、残障人士和家属能看懂“先做什么、带什么、为什么”。

后续可接入审核过的地方政策库、逐页扫描件 OCR、PostgreSQL/pgvector 大规模检索、真实政务接口、账号体系与线上监控。
