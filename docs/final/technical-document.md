# Smart AI 技术文档

## 1. 项目概述

Smart AI（明白办）面向老年人、残障人士、家属和低数字素养人群，将公共
服务办理需求转化为清楚、可确认、可追溯的任务流程。

## 2. 用户痛点与场景

- 政策表述复杂，不清楚办理顺序；
- 地区、年份等信息不全，容易用错政策；
- 不确定材料是否准备齐全；
- 老年人需要大字体、语音和家属协助。

首期范围：居民医保、高校学生资助、老年与残障服务材料办理。

## 3. 功能架构

首页、无障碍设置、任务工作台、材料信息检查、文档解析、演示指南、家属协助、
政策管理和健康检查组成主要界面；Route Handlers 提供任务、对话、政策检索、
材料元数据、文档文本解析和风险确认接口。

## 4. 系统总体架构

前端使用 Next.js App Router、React、TypeScript；服务端使用 Next.js Route
Handlers。演示任务保存在进程内存，匿名会话通过 HttpOnly Cookie 隔离。
DeepSeek 为可选事项识别/摘要层；Prisma/PostgreSQL/pgvector 仅作后续扩展预留，
当前运行路径未接入。

## 5. 任务与 Agent 工作流

任务按理解、追问、检索、材料检查、人工确认推进。未识别事项先追问；医保
事项需要地区和年份；没有适用证据时 fail-closed。事项分类可选调用 DeepSeek
做结构化识别，未配置或调用失败时回退规则；风险分级仍由规则完成，不应表述
为模型判断。

## 6. 政策证据

证据对象包含事项类型、地区、生效/失效日期、条款、来源、相关度和适用理由。
只有事项、地区、时间及演示查询词匹配时才返回。当前唯一政策内容是虚构样例，
不能作为真实政策依据。

## 7. 多模态与材料

浏览器可用时使用原生 Web Speech API。任务工作台的材料检查只接收 MIME 类型
和文件大小，不接收文件字节、不执行 OCR、不生成虚构质量分。

独立的 `/documents` 页面支持 PDF、DOCX、TXT 的文本提取：服务端在请求内读取
文件并返回文本预览，不保存文件；扫描版 PDF 和图片 OCR 尚未启用。

## 8. 隐私、安全与审计

任务创建及追问在进程内保存前对手机号/身份证号脱敏；发送给 DeepSeek 的文本
同样先脱敏。任务 ID 使用 UUID；页面及变更接口检查匿名会话归属。会话和任务
在进程内，服务重启丢失、24小时过期。审计只记录任务 ID、事件类型、风险级别
与时间。知情确认不等于正式办理。

## 9. 无障碍设计

支持 100%、125%、150%、175% 字体、高对比度、键盘焦点、跳过导航、文字替代、
语音输入/播报降级和家属协助清单。设置和清单仅存本机浏览器。

## 10. API 与异常处理

API 使用 Zod 校验；客户端提供 15 秒超时、网络错误提示及保留输入的重试。
健康接口报告 demo、process-memory、DeepSeek 是否配置及 OCR 未启用。
`POST /api/documents/parse` 接收 multipart 文件，限制 10MB，返回文本、页数、
字数与是否截断；解析失败返回 415/422 等可控错误。

## 11. 数据模型

Prisma schema 预留 User、Task、Message、Document、PolicyChunk、Evidence。
当前任务仍在内存中；正式运行前需实现持久化、授权和数据生命周期。

## 12. 测试与结果

21 项单元测试覆盖脱敏、确认、会话、检索边界、超时和文档文本提取。16 项
Playwright 测试覆盖桌面与 390px 移动布局。4 并发、20 条本地规则流程零失败，
P95 34ms；不代表模型/OCR 延迟或公网 SLA。

## 13. 部署

提供 Next standalone、Docker 单实例、健康检查、CI 和手动 GHCR 工作流。公网
部署未执行；单进程内存意味着不支持多副本和负载均衡。DeepSeek 密钥通过服务端
环境变量注入，不写入镜像或仓库。

## 14. 创新点

1. 将公共服务咨询拆分为用户可见的任务状态，而非普通聊天框；
2. 政策结论绑定证据，证据不足明确兜底；
3. 可选 DeepSeek 做事项识别与摘要，未配置时规则回退；
4. 无障碍、家属协助和人工确认纳入主流程；
5. 对敏感信息、材料读取和正式提交设定清楚边界。

## 15. 社会价值与展望

系统降低公共服务的数字门槛。后续可接入审核过的地方政策库、真实 OCR、
结构化模型输出、数据库权限、人工服务转接及部署监控。
